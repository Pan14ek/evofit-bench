## Existing evidence paths and limits

- `experiments/pilots/run_pilot01_measurement.py` reuses Locust, the fixed PILOT-01 workload, and existing runtime sampler. Its source checks and output identifiers are specific to PILOT-01; reuse its workload and aggregate parser, not its old run records or S0/S1 controller as a PILOT-02 experiment.
- `scripts/exp01_evidence.py` and `scripts/exp01_evidence_runtime.py` generate validated A0.1 CI/runtime evidence, raw snapshots, and a manifest. They do not produce the Locust p95 record or targeted atomicity-test record.
- EXP-01/02's existing schemas bind source, stage, evaluator, metric, raw output and hashes, but do not represent all four inherited A0 rows in one PILOT-02 evidence document. A versioned PILOT-02 inventory/results/manifest layer is therefore required; it must reference the existing EXP-01 bundle for runtime evidence rather than copying or fabricating it.
- `experiments/execution/tooling/b0.py` currently supplies the frozen A0 Import Linter artifact only. The generic candidate validator requires exact artifact bytes for every active candidate row. Any additional binding must be a prospective, versioned DEVELOPMENT input admitted through the verified Method P path; it must not edit the frozen A0 config/catalog, patch a materialized candidate, or weaken validation.
- Executing an evaluator and validating its artifact do not prove pair semantics, applicability authority, coverage, or governance acceptance. Those outcomes remain subject to the existing Method P rules and TEST_ONLY boundary.

## Prospective execution plan

Run a fresh Locust measurement on the pinned A0.1 application tree using the existing task file and a preserved, versioned workload; run the existing targeted pytest atomicity test against a dedicated disposable PostgreSQL database; run EXP-01 against the same A0.1 app tree for runtime metrics; then validate a versioned four-row evaluator binding and rerun existing Method P. Keep evaluator execution/provenance distinct from semantic pair proofs and from the two PILOT-02 architecture-compliance operations. Save results only under a unique `experiments/results/<run-id>/`, preserve V1–V4 archives, and archive/checksum the completed run. This inventory records source availability only; no new measurement has yet been made.
