## Bounded ΔA5 scope proposal

A0.5 introduces the engineering requirement that each capability owns its repository, ORM models, and tables while preserving the existing public interfaces and dependency directions. The A0.5 state manifest declares that requirement and names the four owners plus the single model-registry exception. The same manifest states that the A0.4 application tree already meets the ownership patterns; the state transition is a policy-enforcement milestone, not an application refactor.

For a narrowly bounded `CI_TEST` source-evaluation investigation, the author proposes retaining the two unchanged controls `AC_PUBLIC_API` and `AC_MODULE_GRAPH` as regression controls and adding `AC_DATA_OWNERSHIP` as the evaluator directly aimed at the new source-level ownership condition. This is a proposed technical scope for independent decision, not a change to the 18-row applicability inventory or an assertion that any other obligation is INACTIVE. All unselected obligations and all representation–obligation validity rows remain UNKNOWN. CI source evaluation cannot establish runtime, deployment, performance, reliability, database-permission, or full mandatory-obligation coverage claims.

The historical positive and negative cases support only that the named implementations produced those recorded outcomes for those exact source bytes. Independent review must decide whether the configurations semantically represent their intended obligations, whether the source scope is complete for the bounded question, and whether the proposed `CI_TEST` boundary is acceptable.
